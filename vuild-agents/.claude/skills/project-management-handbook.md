# プロジェクト管理ハンドブック

## このスキルの目的

VUILDのプロジェクト管理における標準手法・テンプレート・判断基準を定めたマニュアル。
PM部のエージェントが統一された方法でプロジェクトを管理するための基準書。

---

## 1. プロジェクトライフサイクル

```
① 受注・キックオフ → ② 計画 → ③ 設計 → ④ 製造 → ⑤ 施工 → ⑥ 引渡し → ⑦ 振り返り
```

### 各フェーズのゲート基準

| フェーズ | 完了条件（ゲート通過基準） |
|---|---|
| ① 受注・KO | 契約締結済み、PJ計画書ドラフト完成 |
| ② 計画 | PJ計画書承認済み、WBS完成、キックオフ会議実施 |
| ③ 設計 | 設計図承認済み、加工データ作成完了 |
| ④ 製造 | 全部材の加工完了、品質検査合格 |
| ⑤ 施工 | 施工完了、施主検査合格 |
| ⑥ 引渡し | 引渡書類一式提出、入金確認 |
| ⑦ 振り返り | レトロスペクティブ実施、教訓登録 |

## 3. WBS作成基準

### 基本構成（建築PJ標準）
```
1. プロジェクト管理
   1.1 計画策定
   1.2 進捗管理
   1.3 報告・会議
2. 設計
   2.1 要件定義
   2.2 コンセプト設計
   2.3 基本設計
   2.4 実施設計
   2.5 製作図
3. 製造
   3.1 材料調達
   3.2 加工データ作成
   3.3 CNC加工
   3.4 品質検査
   3.5 梱包・出荷
4. 施工
   4.1 現場準備
   4.2 搬入
   4.3 組立
   4.4 仕上げ
   4.5 施主検査
5. 引渡し
   5.1 書類作成
   5.2 引渡し
   5.3 請求・入金
```

### WBS作成ルール
- 最下位タスクは **5営業日以内** で完了できる粒度に分解
- 各タスクに **担当者・開始日・完了日・成果物** を設定
- 依存関係（先行タスク）を明示
- バッファは全体工期の **15〜20%** を確保

### 週次進捗レポートテンプレート
```markdown
# 週次進捗レポート
- PJ名:
- 報告日: YYYY/MM/DD
- 報告者:

## 全体ステータス: 🟢青信号 / 🟡黄信号 / 🔴赤信号

## 今週の実績
-

## 来週の予定
-

## 課題・リスク
| 課題 | 影響 | 対応策 | 担当 | 期限 |
|---|---|---|---|---|

## 判断依頼事項
-
```

### 信号判定基準
| 信号 | 条件 |
|---|---|
| 🟢 青 | スケジュール±3日以内、予算±5%以内、重大課題なし |
| 🟡 黄 | スケジュール4〜10日遅延、予算5〜15%超過、対応中の課題あり |
| 🔴 赤 | スケジュール10日超遅延、予算15%超過、未対応の重大課題あり |

## 5. リスク管理

### リスク評価マトリクス

|  | 影響度: 低 | 影響度: 中 | 影響度: 高 |
|---|---|---|---|
| **確率: 高** | 🟡 中 | 🔴 高 | 🔴 最高 |
| **確率: 中** | 🟢 低 | 🟡 中 | 🔴 高 |
| **確率: 低** | 🟢 最低 | 🟢 低 | 🟡 中 |

### VUILDの建築PJでよくあるリスク
| リスク | 影響度 | 対策 |
|---|---|---|
| 設計変更の頻発 | 高 | 設計フリーズ日を設定し、以降の変更は追加費用で対応 |
| 材料の品質ばらつき | 中 | テストカットの実施、予備材の確保 |
| 加工機の故障 | 高 | 定期メンテナンス、外注先の事前確保 |
| 現場寸法の相違 | 中 | 事前現場測量の徹底 |
| 天候による施工遅延 | 中 | スケジュールにバッファを確保 |
| クライアント承認の遅延 | 中 | 承認期限を契約時に明記 |

## 6. コミュニケーション計画

### 会議体
| 会議 | 頻度 | 参加者 | 目的 |
|---|---|---|---|
| PJキックオフ | PJ開始時 | 全関係者 | PJ概要共有・キックオフ |
| 週次定例 | 毎週 | PJメンバー | 進捗確認・課題共有 |
| 設計レビュー | フェーズ完了時 | 設計チーム+PM | 設計品質の確認 |
| クライアント報告 | 月次 | PM+クライアント | 進捗報告・方針確認 |
| 振り返り | PJ完了後 | 全関係者 | 教訓の抽出・改善 |

## 7. NG例・よくあるミス

| ミス | 影響 | 正しい対応 |
|---|---|---|
| WBSなしでPJ開始 | タスク漏れ・遅延 | PJ開始前にWBS作成を必須化 |
| 口頭だけの合意 | 「言った言わない」問題 | 決定事項は必ず書面化 |
| バッファなしの工程 | 遅延が即クリティカルに | 全体工期の15〜20%のバッファ |
| 課題を報告だけで放置 | 課題が拡大 | 課題には必ず対策・担当・期限を設定 |
| 設計フリーズなしで製造開始 | 手戻り・追加コスト | 設計承認後に製造開始のゲートを設置 |
