# 業務改善ガイド

## このスキルの目的

VUILDの社内業務フローの分析・改善・標準化を推進するためのマニュアル。
業務改善・オペレーション部のエージェントが体系的に改善を進めるための基準書。

---

## 1. 業務改善の基本フレームワーク

### ECRSの原則（改善の4原則）

| 順序 | 原則 | 意味 | 例 |
|---|---|---|---|
| 1 | Eliminate（排除） | そもそもやめられないか | 不要な承認フローの廃止 |
| 2 | Combine（結合） | まとめられないか | 2つの会議を1つに統合 |
| 3 | Rearrange（再配置） | 順番を変えられないか | レビューを設計初期に前倒し |
| 4 | Simplify（簡素化） | もっとシンプルにできないか | テンプレートの導入 |

**重要**: 必ず E→C→R→S の順で検討する。いきなり「簡素化」に飛ばない。

---

## 2. 業務改善プロセス

```
① 現状把握 → ② 課題特定 → ③ 改善案設計 → ④ 検証 → ⑤ 導入 → ⑥ 効果測定 → ⑦ 定着
```

### 各ステップの詳細

#### ① 現状把握
- 業務フローの可視化（フローチャート作成）
- 業務量の定量化（時間・頻度・関係者数）
- 担当者へのヒアリング（困っていること・非効率だと感じること）

#### ② 課題特定
- ボトルネックの特定（最も時間がかかる/滞留する工程）
- ムダの特定（重複作業・手戻り・待ち時間）
- 根本原因分析（なぜなぜ分析で真因に到達）

#### ③ 改善案設計
- ECRS原則に基づく改善案の策定
- To-Beフローの設計
- 改善効果の試算（時間・コスト・品質の改善幅）
- 導入リスクの評価

#### ④ 検証
- パイロット運用（小規模チーム or 1PJで試行）
- フィードバックの収集
- 改善案の修正

#### ⑤ 導入
- マニュアル・テンプレートの整備
- 関係者への説明会・トレーニング
- 段階的なロールアウト

#### ⑥ 効果測定
- 改善前後のKPI比較
- 定量効果（時間削減・エラー率低減・コスト削減）
- 定性効果（満足度・ストレス軽減）

#### ⑦ 定着
- 定期的なモニタリング（月次チェック）
- 逸脱の早期発見・是正
- 継続的改善（PDCAサイクル）

## 3. 業務フロー可視化テンプレート

### フローチャート記法
| 図形 | 意味 |
|---|---|
| 角丸四角形 | 開始/終了 |
| 四角形 | 処理/作業 |
| ひし形 | 判断/分岐 |
| 平行四辺形 | 入力/出力（データ・文書） |
| 矢印 | 流れの方向 |

```markdown
- 関係者:

[フローチャートを記載]

### 課題
1.
2.

### To-Be（改善後フロー）

### 改善効果

```

## 4. VUILDの主要業務フロー

### 改善対象となる主要業務

| 業務 | 頻度 | 現状の課題 | 改善方向性 |
|---|---|---|---|
| 見積作成 | 月10件 | 毎回手作業、時間がかかる | テンプレート化+過去データ活用 |
| 設計レビュー | PJ毎 | チェック漏れが発生 | チェックリストの標準化 |
| 加工データ受渡し | PJ毎 | メール添付、版管理が曖昧 | 共有フォルダ+命名規則統一 |
| 進捗報告 | 週次 | 各自フォーマットが違う | テンプレート統一 |
| 材料発注 | 月数回 | 在庫確認が手動 | 在庫管理シート+発注アラート |
| 請求処理 | 月次 | 手入力が多い | 自動化（会計ソフト連携） |
| ナレッジ共有 | 随時 | 属人化、共有されない | ナレッジベース構築 |

## 6. 自動化の判断基準

### 自動化すべき業務の特徴
| 特徴 | 説明 |
|---|---|
| 反復性 | 同じ手順を繰り返す（月4回以上） |
| ルールベース | 判断基準が明確（if-thenで表現可能） |
| 大量処理 | 1回あたりのデータ量が多い |
| エラーリスク | 手作業ミスが発生しやすい |
| 時間消費 | 1回30分以上かかる |

### 自動化の優先順位マトリクス

|  | 効果: 大 | 効果: 小 |
|---|---|---|
| **難易度: 低** | 最優先（すぐやる） | 余裕があればやる |
| **難易度: 高** | 計画的に取り組む | 見送り |

### 自動化のROI計算
```
年間削減時間 = 1回の削減時間 × 年間実行回数
年間削減コスト = 年間削減時間 × 時間単価
ROI = 年間削減コスト ÷ 開発コスト
```
**目安**: ROI > 2.0（2年で投資回収）を基準に判断

## 7. NG例・よくあるミス

| ミス | 影響 | 正しい対応 |
|---|---|---|
| 現状分析なしで改善案を出す | 的外れな改善 | 必ず現状を定量的に把握してから |
| 大規模改善を一気に導入 | 混乱・反発 | パイロット→段階的展開 |
| 効果測定をしない | 改善の成否が不明 | 改善前にKPIを設定、導入後に比較 |
| 現場の声を聞かない | 実態に合わない改善 | 担当者ヒアリングを必ず実施 |
| ツール導入が目的化 | ツールに振り回される | 課題解決が目的、ツールは手段 |
| マニュアルなしで運用開始 | 属人化が再発 | 改善後のフローを必ず文書化 |
| 「改善したから完了」で終わる | 元に戻る | 定期モニタリングで定着を確認 |
