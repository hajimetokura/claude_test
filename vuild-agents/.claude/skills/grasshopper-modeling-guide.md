# Grasshopperモデリングガイド

## このスキルの目的

Rhinoceros + Grasshopperを用いたパラメトリック設計の標準手法・品質基準・VUILDならではのワークフローを定めたマニュアル。
Grasshopperモデラー田中を中心に、設計部全員が参照する。

---

## 1. GH定義ファイルの構成規則

### 標準レイアウト

GH定義はキャンバス上で **左から右へ** データが流れるように配置する。

```
[入力パラメータ] → [形状生成] → [変換・加工] → [出力・Bake]
     (左端)          (中央左)       (中央右)        (右端)
```

### グループ分けルール
| グループ色 | 用途 |
|---|---|
| オレンジ | 入力パラメータ（Number Slider等） |
| 緑 | 形状生成（メインのジオメトリ生成） |
| 青 | 変換・加工（Move, Rotate, Boolean等） |
| 紫 | 解析・評価（面積計算、構造解析等） |
| 赤 | CNC加工データ出力 |
| グレー | ユーティリティ（データ整理、リスト操作等） |
| 黄 | 出力・Bake・Export |

### 命名規則
- **GH定義ファイル**: `[PJ番号]_[用途]_v[版数].gh`
  - 例: `V2024-015_pavilion-structure_v03.gh`
- **グループ名**: `[番号]_[機能名]`（例: `01_Input Parameters`）
- **パネル（README）**: 定義の冒頭に必ず配置し、以下を記載
  - 定義の目的
  - 使い方（どのSliderを操作するか）
  - 出力先（Bakeするレイヤー）
  - 作成者・更新日・版数

## 2. パラメータ設計基準

### Number Sliderの設定
| パラメータ種別 | 型 | 最小値 | 最大値 | ステップ |
|---|---|---|---|---|
| 全体寸法（mm） | Integer/Float | 材料制約の最小 | 搬送制約の最大 | 1〜10 |
| 部材厚（mm） | Float | 使用材料の最薄 | 使用材料の最厚 | 0.1 |
| 分割数 | Integer | 1 | 合理的な最大値 | 1 |
| 角度（度） | Float | 0 | 360 | 0.1〜1 |
| 比率 | Float | 0 | 1 | 0.01 |

### パラメータ設計ルール
1. **外出し**: 変更の可能性があるすべての値をNumber Sliderで外出し
2. **範囲制限**: 物理的に不可能な値は範囲外に設定
3. **デフォルト値**: 最も標準的な値をデフォルトに設定
4. **命名**: Sliderに分かりやすい名前を付ける（「幅」「高さ」等、日本語可）
5. **グルーピング**: 関連するSliderはまとめてオレンジグループに配置

## 3. データツリー管理

### 基本原則
- データツリーの構造は **意味のある階層** にする（ブランチ = 部材グループ等）
- **Graft / Flatten** の乱用を避ける（必要な場合はコメントで理由を記載）
- **Null / Invalid** データの処理を必ず入れる（Clean Treeコンポーネント等）

### よくあるデータツリーのパターン
| パターン | ツリー構造 | 用途 |
|---|---|---|
| 部材リスト | {0}, {1}, {2}... | 各ブランチに1部材 |
| 階層別 | {0;0}, {0;1}, {1;0}... | 階数×部材種別 |
| グリッド | {x;y} | グリッド上の配置 |

## 4. CNC加工データ出力ワークフロー

### GHからCNC加工データを出力する標準手順

1. **3Dモデルの2D展開**
   - Unroll / Orient to Planeで部材を展開
   - 材料面に投影（XY平面にFlatten）

2. **加工ラインの分類**
   - 切断線（Outside Cut）→ 赤レイヤー
   - 穴加工（Inside Cut）→ 青レイヤー
   - 彫刻線（Engrave）→ 緑レイヤー
   - ドリル穴（Drill）→ 黄レイヤー

3. **ネスティング**
   - OpenNestプラグインまたは手動配置
   - 材料サイズ: 2440mm × 1220mm（4×8合板）
   - 部材間隔: ビット径 + 2mm以上
   - 歩留まり率を計算・表示

4. **出力**
   - DXF形式でエクスポート（レイヤー別）
   - 部材番号をテキストとして配置
   - ネスティング図を図面として出力

### 加工制約チェックリスト（GH側で確認）
- [ ] 最小内角R ≧ ビット径の半径（3mm以上）
- [ ] 最小部材幅 ≧ 10mm（ビット径 + 余裕）
- [ ] スロット幅 ≧ 材料厚 + クリアランス
- [ ] 穴径 ≧ 3mm（最小ドリル径）
- [ ] 材料サイズ内にすべての部材が収まっている

## 6. コーディング規則（C# / Python Script）

### GH内でスクリプトを使う場合のルール
1. **コメント**: 冒頭に目的・入出力を記載
2. **変数名**: 英語のcamelCase（例: `panelWidth`, `jointDepth`）
3. **エラーハンドリング**: 不正入力時はエラーメッセージを出力（無言で失敗しない）
4. **パフォーマンス**: ループ内でのRhinoCommon呼び出しを最小化
5. **テスト**: エッジケース（0、負数、空リスト）での動作確認

### サンプル（C# Script）
```csharp
// 目的: 部材にジョイント用の切り欠きを生成
// 入力: crv (Curve) - 部材の外形, depth (double) - 切り欠き深さ
// 出力: result (Curve) - 切り欠き付き外形

if (crv == null) {
    AddRuntimeMessage(GH_RuntimeMessageLevel.Error, "入力カーブがnullです");
    return;
}
if (depth <= 0) {
    AddRuntimeMessage(GH_RuntimeMessageLevel.Warning, "深さは正の値を指定してください");
    return;
}
```

## 7. NG例・よくあるミス

| ミス | 影響 | 対策 |
|---|---|---|
| グループ分けなしの定義 | 他者が理解できない | 必ずグループ化＋ラベル付け |
| Sliderの範囲が無制限 | 不正な値で定義が壊れる | 物理的制約に基づく範囲設定 |
| FlattenとGraftの乱用 | データ構造が破綻 | ツリーの意味を意識した設計 |
| READMEパネルなし | 使い方が分からない | 冒頭に必ずREADMEパネルを配置 |
| 版数管理しない | 前の版に戻れない | ファイル名に版数、旧版は保存 |
| 加工制約を無視した設計 | 加工できない | チェックリストで事前確認 |
| 重い定義（更新10秒以上） | 作業効率低下 | データ量の削減、Timerの活用 |
